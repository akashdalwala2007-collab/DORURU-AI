ESP32-S3 Hardware & Peripheral Constraints (Verify Against Framework/Board Package):
- UART0 Pin Conflict on D6/D7: D6 (GPIO43, MAX98357A LRC) and D7 (GPIO44, ILI9341 D/C) are the ESP32-S3 default UART0 TX/RX pins. Avoid UART0 serial logging and ensure bootloader/hardware UART activity does not toggle GPIO43/GPIO44 during operation. Use native USB CDC for Serial debugging.
- I2S Peripheral Allocation: On ESP32-S3, PDM RX support is tied to I2S_NUM_0. Reserve I2S_NUM_0 for the onboard PDM microphone (GPIO41/GPIO42) and assign I2S_NUM_1 to the MAX98357A speaker (D4/D5/D6). - Custom SPI Routing: Standard XIAO ESP32-S3 default SPI pin macros do not match the confirmed display wiring. Explicitly configure custom SPI pins in software: SCK = GPIO9 (D10), MOSI = GPIO8 (D9), MISO = -1, CS = -1, while preserving D/C = GPIO44 (D7) and RESET = GPIO7 (D8).
- Octal PSRAM: XIAO ESP32-S3 Sense includes 8MB Octal PSRAM (OPI). Configure and verify OPI PSRAM support in build settings and runtime checks rather than assuming it is enabled by default.

Do not reassign pins, change wiring, or silently add peripherals. Convert D-pin labels to GPIO numbers only after checking the exact XIAO ESP32-S3 pin mapping and existing working sketches. The current known mapping commonly used for this board is D0=GPIO1, D1=GPIO2, D2=GPIO3, D3=GPIO4, D4=GPIO5, D5=GPIO6, D6=GPIO43, D7=GPIO44, D8=GPIO7, D9=GPIO8, D10=GPIO9; verify against the board definition used by this repository before implementation.

Critical ESP32-S3 Hardware & Configuration Requirements for Phase 2:
1. UART0 Conflict & USB CDC Logging:
   - D6 (GPIO43 = MAX98357A LRC) and D7 (GPIO44 = ILI9341 D/C) are the ESP32-S3 default UART0 TX/RX pins.
   - Do not use UART0 for Serial logging, as UART0 traffic will toggle GPIO43/GPIO44 and corrupt speaker audio or display commands.
   - Configure native USB CDC for Serial debug output. If using PlatformIO, inspect and verify compatibility of flags such as ARDUINO_USB_CDC_ON_BOOT=1 and ARDUINO_USB_MODE=1 against the repository's actual XIAO ESP32-S3 Sense board definition and framework version—do not blindly copy build flags. Ensure hardware UART0/bootloader output does not unintentionally disturb GPIO43/GPIO44 during normal operation.
2. Reserved Onboard PDM Microphone & Camera Pins:
   - Explicitly reserve GPIO41 (PDM_DATA) and GPIO42 (PDM_CLK) in the central pin map for the onboard XIAO ESP32-S3 Sense PDM microphone.
   - Explicitly reserve the internal camera pins for the OV3660 camera.
   - Never assign GPIO41, GPIO42, or camera pins to motors, display, speaker, sensors, or diagnostics.
3. Coordinated I2S Peripheral Allocation:
   - On ESP32-S3, PDM RX is supported on I2S_NUM_0. Reserve I2S_NUM_0 strictly for the onboard PDM microphone (GPIO41/GPIO42).
   - Assign I2S_NUM_1 to the MAX98357A speaker output (DIN=D4/GPIO5, BCLK=D5/GPIO6, LRC=D6/GPIO43).
   - Coordinate the microphone input interface and speaker output wrapper so they do not compete for the same I2S peripheral. Verify that the active ESP-IDF/Arduino framework version and audio libraries support this I2S_NUM_0 (PDM RX) + I2S_NUM_1 (I2S TX) assignment; if framework-specific constraints exist, document the verified alternative before implementation.
4. Custom SPI Routing & Display CS/Reset Handling:
   - Do not rely on default XIAO ESP32-S3 SPI macros or default pin order.
   - Configure custom SPI pins explicitly: SCK = GPIO9 (D10), MOSI = GPIO8 (D9), MISO = -1, CS = -1, with D/C = GPIO44 (D7) and RESET = GPIO7 (D8).
   - Because physical CS is intentionally wired to GND (permanently selected), configure software CS = -1 (where supported by the display library) and perform an explicit hardware reset pulse on D8 (GPIO7) during display initialization.
   - Document that VCC is connected to VBUS/5V (valid only for display breakouts with an onboard regulator and 3.3V-compatible SPI logic) and that if a future display failure occurs due to CS=GND, rewiring to a GPIO CS pin requires explicit user approval.
5. Octal PSRAM (8MB OPI) Configuration & Runtime Check:
   - Configure and verify 8MB Octal PSRAM support in Phase 2 so it is ready for Phase 5 camera buffers and Phase 10 wake-word models.
   - In PlatformIO, verify compatibility of settings such as board_build.arduino.memory_type = qio_opi and -DBOARD_HAS_PSRAM against the actual board package and framework version before applying. In Arduino IDE/CLI, verify the OPI PSRAM board option.
   - Implement a runtime PSRAM availability and size check at boot (logging actual detected PSRAM) with a safe, graceful fallback state if PSRAM is unavailable. Do not claim that enabling PSRAM flags alone guarantees camera or ESP-SR compatibility.

IMPORTANT HARDWARE LIMITATIONS TO KEEP VISIBLE
----------------------------------------------
- Normal OV3660 camera does not by itself guarantee obstacle avoidance, localization, person following or safe navigation.
- MX1508 is a motor driver, not a wheel encoder.
- Without encoders, distance and turning precision are approximate.
- Without validated obstacle sensors, autonomous obstacle avoidance must remain disabled.
- Do not assume a microSD slot/card is present.
- Do not assume a battery voltage/current rating, regulator capacity, or motor stall current rating; these require physical datasheet and circuit verification.
- Do not power motors from ESP32 3.3V. Use a suitable motor supply and common ground as required by the actual circuit and component specifications.
- Display VCC on VBUS/5V is valid only if the display breakout has an onboard regulator with 3.3V-compatible SPI logic; CS tied to GND requires CS = -1 in software and a hardware reset pulse on D8 (GPIO7).
- D6 (GPIO43) and D7 (GPIO44) overlap default UART0 TX/RX; use native USB CDC for Serial logging so UART0 does not interfere with the speaker or display.
- GPIO41 (PDM_DATA) and GPIO42 (PDM_CLK) on I2S_NUM_0 are strictly reserved for the onboard PDM microphone, while MAX98357A uses I2S_NUM_1; simultaneous operation and ESP-SR compatibility must be verified on the actual framework/board setup.
- The fixed user-approved connections are not an invitation to rewire. If a real electrical safety or hardware compatibility issue is found, stop and explain before changing anything.
